# アンケートゲーム（GitHub Pages ＋ Firebase 版）

サーバー不要の静的版。HTML/JS を GitHub Pages に置き、リアルタイム同期は Firebase Realtime Database（無料枠）に任せる。
URL が固定なので QR コードを事前に印刷でき、当日ノートPCが落ちても止まらない。

ゲームの内容・ルール・画面は Node 版（`../survey-game`）と同じ。

| ページ | 用途 |
|---|---|
| `index.html` | 参加者（スマホ）。名前入力 → 練習 → 「本番に参加する」 → 回答・結果・得点 |
| `screen.html` | 会場スクリーン。QR、問題、集計中、棒グラフ演出、最終ランキング |
| `admin.html` | 司会用。人数・回答済み、進行ボタン |

## 初回セットアップ（30分くらい・1回だけ）

### 1. Firebase プロジェクトを作る

1. https://console.firebase.google.com/ → 「プロジェクトを追加」（Google アナリティクスは不要）
2. 左メニュー「構築」→「Realtime Database」→「データベースを作成」
   - ロケーションは `asia-southeast1`（シンガポール）でOK
   - セキュリティルールは「テストモード」で作成（後で差し替える）
3. 「構築」→「Authentication」→「始める」→ ログイン方法で **「匿名」を有効化**
   - 参加者を匿名ユーザーとして識別するために使う（メールなどは一切不要）
4. 「プロジェクトの設定」（歯車）→ 下の「マイアプリ」→ ウェブ（`</>`）→ アプリのニックネームを入れて登録
   - 表示される `firebaseConfig = { ... }` の中身を **`js/firebase-config.js`** に貼る
   - `databaseURL` が含まれていなければ、Realtime Database のページ上部に出ている URL（`https://xxxx-default-rtdb.asia-southeast1.firebasedatabase.app`）を追記する
5. 「Realtime Database」→「ルール」タブ → `database.rules.json` の中身を貼り付けて「公開」

### 2. GitHub Pages に置く

1. GitHub で新しいリポジトリを作る（Public）
2. このフォルダの中身（`index.html` `screen.html` `admin.html` `js/`）を push
3. リポジトリの Settings → Pages → Source を「Deploy from a branch」、Branch を `main` / `/ (root)` にして保存
4. 数分後 `https://<ユーザー名>.github.io/<リポジトリ名>/` で開ける

もし参加画面で「設定エラー」や「auth/…」のエラーが出たら、Firebase の Authentication → Settings → 「承認済みドメイン」に `<ユーザー名>.github.io` を追加する。

### 3. 管理キーを決める

`.../admin.html` を最初に開くと「管理キーが未設定」と出るので、好きな文字列（4文字以上）を決めて「設定して接続」。
以後、管理画面はそのキーを入れないと操作できない。キーは Firebase の `config/adminKey` に入っているので、忘れたら Realtime Database の「データ」タブで見られる。

## 当日の流れ

- 会場スクリーンPC: `.../screen.html` を全画面（F11）。QR と URL が出る
- 司会のスマホ/タブレット: `.../admin.html`（キーはブラウザに記憶される）
- 参加者: QR から `.../` （index.html）

進行ボタンの順:

```
練習問題 回答受付開始 → 回答締切 → 結果発表（グラフ） → 練習終了 → 本番参加の受付へ
→ 第1問へ → 回答受付開始 → 回答締切 → 結果発表（グラフ） → 次の問題へ … 
→（最終問題の結果発表後）最終ランキング表示へ → 次の順位を表示（3位 → 2位 → 1位）
```

- 「次の問題へ」で問題文がスクリーンに出る（まだ回答不可）。司会が読み上げてから「回答受付開始」。
- 締切を間違えたら「問題ジャンプ・リセット」内の「回答受付をやり直す」。
- **別の会で使うとき**は管理画面の「全リセット」で参加者・回答・得点を消す（管理キーは残る）。
  同じ Firebase で同時に複数の会をやるなら `js/firebase-config.js` の `ROOM` を変える。

## 得点ルール（実装どおり）

- 自分の答えが少数派 → 1点。0票の選択肢は少数派にしない。同数なら両方少数派。全選択肢が同数のときは少数派なし。
- 多数派予想が当たり → 1点。多数派が同数のときは、どちらを予想しても正解。
- 練習問題は得点に入らない。最終ランキングは同点同順位で、3位以内を全員表示。

## 問題の編集

`js/questions.js` を編集して push。`practice` が練習問題、`questions` が本番（この順に出題）。選択肢は2〜6個。

## テスト

```bash
node test/store.test.js
```

Firebase をインメモリでモックし、練習 → 本番参加 → 3問 → 締切取消 → 最終ランキング → リセットまで通す。

## 仕組みと注意

- 全クライアントが Firebase の `/{ROOM}` を購読し、同じロジックで画面を組み立てる。「回答締切」を押した管理画面が集計して `results` に書き、各スマホは自分の回答と `results` から得点を計算する。
- セキュリティルールは「匿名ログイン済みなら読み書き可」。会場の参加者が悪意を持って書き換えることは想定していない（パーティ用途の割り切り）。ブラウザの開発者ツールを使えば他人の回答も見えるので、答えにくい問題は入れないこと。
- Firebase 無料枠（同時接続100・転送10GB/月）で 50〜100人規模は余裕。
- 匿名ユーザーの識別はブラウザに保存されるので、同じスマホで開き直せば復帰できる。別のブラウザで開くと別人になる。
